# MandateGuard

**A re-consent allocator for Indian recurring mandates.** Razorpay AI Buildathon 2026,
Track 3.

India's e-mandate book is about to need re-consent at scale, and a merchant's ability to
ask for it is not free: every message costs money, costs patience, and can itself cause the
revocation it was sent to prevent. MandateGuard treats that as an allocation problem —
**which mandates to ask, on which channel, under a weekly budget** — fits the lapse hazard
on real subscriber data, prices each ask in rupees, and **logs every decision it declines to
make** alongside every one it makes.

---

## Run it

```bash
uv sync
uv run mandateguard repro --check
```

**About three minutes** on a plain local disk, no download, no API key. It rebuilds
`docs/results.md`, `docs/img/sweeps.png`, `docs/llm_eval.md` and `docs/img/segments.png`
from the committed 5,079-subscriber slice in `data/sample/`, then fails if a single byte
differs from what is committed. It also prints the two artifacts it **cannot** rebuild from
the sample, and why.

That is GATE 5, and it is the same command CI runs — on a different operating system from
the one these files were committed from.

> **If it takes an hour instead, your checkout is in a cloud-synced folder.** Measured on
> 2026-09-04: identical tree, identical output, **81s against 3,668s** depending only on
> where the derived frames were written. The run reports the directory it is using on its
> first line. Set `MANDATEGUARD_DATA_DIR` to a plain local path and rerun — see
> `.env.example`.

```bash
uv run pytest                                       # 673 tests, 2 opt-in and skipped
uv run mandateguard audit --rail enach --amount 20000   # judge one mandate, clauses named
uv run mandateguard replay --decision-id <id>       # re-run one historical decision
uv run mandateguard verify-ledger <path>            # walk the hash chain
uv run python scripts/compile_policy.py --check     # re-verify 20 rules against the circular
uvicorn mandateguard.app.api:app                    # /allocate /audit /explain /ledger /replay
```

## The result, and the part of it that fails

Six allocation arms over one book, one hazard path, one 12-week horizon. Full table and the
sensitivity plane: [`results.md`](docs/results.md), regenerated by CI.

Against `P1`, the campaign-tool default of contacting everyone eligible, the knapsack arm
`P4` retains **1,215.9 mandates against 1,131.9** (+7.42%), causes **0.3 revocations against
90.6**, and does it with **109 asks against 16,236**.

Three things stop that from being a win, all of them in the documents rather than in a
footnote:

* **Against doing nothing at all (`P0`), the lift is +0.05%.** `P0` is what most of these
  mandates already get. That is the honest figure for what selection buys on this book.
* **It fails the one external check available.** LinkedIn's published triple (KDD 2016) is
  volume down, engagement down slightly, complaints down. Here retention moves the **wrong
  way** — cutting asks is not supposed to raise the thing the asks were for.
  [`eval.md` §6](docs/eval.md) runs the comparison and sweeps every backfire rate looking
  for one that reproduces LinkedIn's shape. None does.
* **The segment plot is a negative result, predicted before it was run.** Pinterest's
  inverted U does not appear; this model produces a threshold, and
  [`eval.md` §7](docs/eval.md) explains why the mechanism that would produce one is absent.

## What is actually built

| layer | what it owns |
|---|---|
| `data/` | KKBox → typed parquet → mandate book → person-period frame → the committed sample |
| `risk/` | discrete-time hazard model, its baselines, its calibration |
| `value/` | four rupee terms per (mandate, channel): lapse loss, backfire, fatigue, reachability |
| `allocator/` | six arms, ending in a multiple-choice knapsack; theta is the LP dual on the budget |
| `policy/` | 20 rules compiled from the RBI e-mandate circular, each with a clause and a verbatim quote |
| `agent/` | the four LLM jobs — compile, audit, compose, explain. **None of them decides** |
| `safety/` | shadow mode by default, spend cap, kill switch, a four-rung degradation ladder |
| `ledger/` | append-only hash-chained JSONL: every decision, **asked and not-asked**, replayable |
| `eval/` | the week loop, the forecast, the sweeps, the holdout, the shape check, `repro` |

The two boundaries worth knowing before reading any code: **the model never selects
mandates** ([ADR 0004](docs/adr/0004-the-model-does-not-decide.md)) and **`Guard.authorise`
is the only path to acting** ([ADR 0005](docs/adr/0005-shadow-mode-and-the-degradation-ladder.md)).
[`architecture.md`](docs/architecture.md) has the rest, with the alternative rejected in
each case.

weaker. They are recorded where they were used, not only where they were found.

## What this is not

* **Not validated on Indian mandate data.** KKBox is a Taiwanese music subscription
  dataset. The rail mix is assigned from a hash. `mapping.md` §3.9 and `limitations.md` §4.
* **Not measured.** Uplift and backfire have no public measurement, so the results are
  reported as a region ([`results.md`](docs/results.md) §4) rather than a point — and the
  headline's sign depends on where in that region you stand.
* **Not live.** Shadow mode is the default and the HTTP response says `acted: false` as a
  field, not as a promise.
* **No frontend.** T5.6 was cut in the documented cut order. The charts are PNGs.

Full data lives outside the repository via `MANDATEGUARD_DATA_DIR` (see `.env.example`) —
the raw files are ~4 GB. Nothing in the quickstart above needs them.
