## 3. Abstention, measured in both directions

Abstain recall alone is a metric a broken system wins: abstain on everything and it
reaches 100%. Precision is the half that costs something — every abstention is a
person's time, and a system that abstains on mandates it could have graded is a
review queue rather than a product.

| metric | value | reading |
|---|---|---|
| Abstain recall | **100.0%** (5/5) | of the cases that should abstain, how many did |
| Abstain precision | **100.0%** (5/5) | of the cases it abstained on, how many should have |

On the rules arm every abstention comes from clause 2 — the mandate's rail is
outside the framework — so this arm measures whether scope is applied correctly,
not whether the system knows when it is uncertain. The uncertainty half is the
extraction arm, and it is unscored (§5).

**T4.8, the adversarial generator, is cut.** It is CUT #2 in `docs/tasks.md`, and
the reason it is cut is the reason it could not have been faked: a generator's
whole value is producing the cases nobody thought of, and there is no credential
here to run one with. What survives is the measurement — 55 of the 120 cases were
written adversarially on purpose, against the boundaries T4.8 names (Rs.14,999 vs

grandfathered mandate, the Rs.1 lakh cap, a variable mandate with a customer cap),
and `scripts/build_golden.py` states the criterion that sorts them.

The gap above is therefore a real number about a *hand-written* adversarial set,
not about a generated one. A generated set would be harder, and the honest reading
is that this gap is a floor on the true one rather than an estimate of it.

## 5. The model arm, and what it does not say

6 cases need a model to read a free-text record before the
rules can judge it. Each one's expected verdict is an abstention, because the
record genuinely does not determine a field that an applicable rule reads.

| metric | value |
|---|---|
| Cases scored | **0 of 6** |
| Cost per verdict | **not measured** |
| p95 latency | **not measured** |
| Accuracy, abstain precision/recall | **not measured** |

The reason is a single fact and it is not a limitation of the design: no Anthropic
credential was available on the machine where Phase 4 was built, so
`tests/cassettes/` is empty and every extraction request raises a cassette miss.
The rows above are blank rather than estimated. A cost-per-verdict figure derived
from a token count nobody measured would be the exact failure `calibration.md` §5
exists to prevent.

What **is** known, and is a fact about the code rather than a measurement:

* every request carries its own token counts back from the API and is priced at the
  rates in `config/params.yaml`, so cost per verdict is measured the moment a
  cassette exists — it is not estimated then either;
* the Batch API halves that cost, which is why T4.7 specifies it for a 120-case run;
* `llm.spend_cap_usd_per_run` stops a run before it exceeds its budget;
* replayed latency is the latency that was *recorded*, so the p95 this table will
  eventually carry is a measurement of one machine and one network on one day, and
  will be labelled as such.

## 6. What 100% on the rules arm is worth

Less than it looks, and the reason is worth stating plainly.

**The same reader wrote both sides.** The twenty rules and the 114 expectations were
written in the same session, from the same reading of the same circular. A
misreading of clause 8(b) would have gone into the rule *and* into the expectation,
and this table would show 100% either way. That is not what an independent test set
means, and this number must not be presented as one.

What the set is genuinely worth is **forward-looking**: it is 120 statements about
what the circular requires, written down before anyone had a reason to want a
particular answer. The next time a rule is edited — a threshold moved, a guard
loosened — this file is what notices. That is a regression suite with citations,
and it is a real thing to have. It is not external validation.

**The extraction arm is where the model would actually be tested**, and it is the
arm with no numbers. So this document currently measures a rule engine, not an LLM
system, and its title overstates it until a cassette exists.
